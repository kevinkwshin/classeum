## 3. 핵심 흐름

### 3.1 이벤트 만들기

1. 엑셀을 올리면 검증 결과를 보여 준다 (정상·경고·오류 개수, 행 번호와 고칠 방법).
2. 앱이 단어마다 문제를 만들고 미리보기를 보여 준다. 선생님은 [보기 다시 뽑기] [이 짝 같이 내지 않기] [이 문제 빼기]만 누르면 된다.
3. 확인하면 이벤트가 생긴다. 이름은 세트 칸 값, 비어 있으면 `MM-DD 퀴즈`.
4. 이벤트마다 오늘의 보상, 시간, 예상 소요 시간을 보여 준다. 20분이 넘으면 나누기를 제안한다.

### 3.2 반과 첫 등록

선생님은 여러 반을 맡는다 (예: 6개 반, 학생 계정 180명 이상, 한 번에 접속은 30명 안팎). 반마다 학생이 따로 있고 번호는 반 안에서만 겹치지 않으면 된다. 같은 퀴즈 이벤트를 여러 반이 각자 진행하고, 기록·통계는 반별로 남는다. 보상·아이템·발자국은 반과 상관없이 학생 개인 것이다.

0. 선생님이 대기실을 열 때 오늘 들어온 반을 고른다. 그 반 학생만 등록·입장하고, 다른 반 학생 폰은 "지금은 ○반 수업 중"만 본다.
1. 대기실 QR을 찍는다 → 반을 고르고(대기실이 열려 있으면 그 반으로 정해져 있다) 번호와 이름을 직접 쓴다. 등록 전 폰에는 다른 학생 이름을 보여 주지 않는다.
2. 학생 폰과 선생님 화면에 같은 확인 기호(예: `여우 47`)가 뜬다 → 선생님이 승인한다. 요청은 명단과 비교해 표시한다: 명단 확인(같은 번호·이름) · 새 학생(그 번호가 비어 있음, 승인하면 명단에 추가) · 기기 교체(이미 폰이 있는 학생) · 번호 겹침(그 번호에 다른 이름, 승인하면 이름을 바꾼다). 명단 확인과 새 학생은 [모두 승인]으로 한 번에, 나머지와 "같은 이름이 다른 번호에 있음"은 하나씩 확인한다. 명단을 미리 넣는 건 선택이다.
3. 캐릭터를 고른다 (머리 모양, 피부색, 머리색).
4. 다음 주부터는 QR만 찍으면 바로 입장한다. 거절되면 다시 찍는다.
5. 브라우저 데이터 삭제·새 폰: 선생님이 교체를 승인하면 캐릭터와 기록이 이어진다.

### 3.3 한 번의 아레나

| 단계 | 내용 | 시간 |
|---|---|---|
| 대기실 | 입장 QR, 들어온 아바타, 오늘의 보상 카드 | 선생님이 [퀴즈 시작] |
| 원정 | 모든 단어를 한 번씩. 10문항마다 관문(반 정답률, 잠깐 쉬기) | 문항당 평균 약 12초 |
| 다시 도전 | 반 정답률이 70% 미만인 단어 중 낮은 순 최대 5개를 반대 방향으로 다시 | 약 1분 |
| 마무리 | 큰 화면: 반 정답률, 보상 받은 인원. 학생 폰: 내 결과, 보상, 오답 노트 | 약 1분 |

예상 시간: 20단어 약 6분, 40단어 약 11분, 50단어 약 13분 (조기 마감 기준).

### 3.4 한 문항

| 순간 | 프로젝터 | 학생 폰 |
|---|---|---|
| 등장 (0.5초, 라운드 첫 문항은 3·2·1) | 단어가 위에서 떨어지듯 뜨고, 네 칸(① 파랑 ② 주황 ③ 초록 ④ 보라)에 보기 | 미니 운동장(같은 색) + 게임 패드, "준비!" |
| 이동 (최대 15초) | 흐르는 안개. 칸 이름과 "✓ 31/34"만. 마지막 3초는 시계가 주황으로 깜빡 | ↑↓←→로 내 캐릭터가 뒤뚱뒤뚱 걸음 (칸에 들어가면 진동, 내 위치는 나만) |
| 마감 | 모두 자리 잡으면 1초 뒤, 아니면 0초에 | 입력 잠김 |
| 공개 (4초) | 안개가 양옆으로 걷히고 캐릭터가 통통 착지. 정답 칸은 금테·월계수 잎, 캐릭터는 하트 내며 폴짝. 오답 칸은 부풀다 "펑!" 하고 그을린 채 어질어질. 몇 명은 말풍선("야호!", "내 머리…") | 내 캐릭터가 크게: 맞으면 폴짝+하트, 틀리면 펑+그을림, 출발선에 남았으면 쿨쿨. 정답, 틀렸으면 "네가 고른 lend는 빌려주다예요" |
| 다음 | 자동으로 다음 문항 | |

- 반 정답률이 60% 미만이면 공개를 6초로 늘리고 가장 많이 고른 오답을 함께 보여 준다.
- 쓰기(단답형): 폰이 쓰는 중인 답을 0.3초마다 저장해 두고, 시간이 끝나면 저장된 답으로 채점한다. [제출]을 누른 학생만 "다 했다"로 세서, 모두 제출해야 일찍 마감한다.
- 펑은 놀리는 느낌이 아니라 만화처럼 우스꽝스럽게: 오답 칸에 1~2명뿐이면 원래대로 숫자만 보여 주므로 혼자 펑 터지는 학생은 없다.
- 대기실 캐릭터는 둥둥 떠 있다가 가끔 혼자 폴짝/빙글, 눈도 깜빡인다. 폰 첫 화면 캐릭터는 누르면 한마디 하고, 너무 많이 누르면 빙글 돌며 어지러워한다.
- 선생님 단축키: Space 멈춤 · Enter 지금 마감 · ↑ +5초 · S 건너뛰기 · B 화면 가리기(시계도 멈춤). 프로젝터 창에서 눌러도 같다.
- 시간이 모자라면 [종료]로 여기서 마무리한다(낸 문항만으로 보상 판정), 다시 도전만 빼려면 [다시 도전 건너뛰기].
- 건너뛴 문항은 기록·보상·통계에서 뺀다.
- 콘솔의 정답은 공개 전까지 가려 두고 [정답 보기]로 연다 (화면이 미러링돼도 새지 않게).

### 3.5 운동장 규칙

- 4지선다: 왼쪽 위 ①, 오른쪽 위 ②, 왼쪽 아래 ③, 오른쪽 아래 ④. OX: 왼쪽 O, 오른쪽 X.
- 문항마다 모두 가운데 출발선에서 시작한다. 마감 때 출발선에 있으면 미응답.
- 폰: ↑↓←→ 버튼. 키보드가 있으면 방향키. 미니 운동장의 칸을 누르면 그 칸으로 걸어간다.
- 안개 중에는 위치가 프로젝터에 안 보인다. 따라가기를 막기 위해서다.
- 이름표는 기본으로 끔 (켜도 번호만).
- 공개 때 아바타는 멈춘 자리가 아니라 칸 안에 줄 맞춰 선다. 오답 칸에 1~2명만 있으면 아바타 없이 숫자만, 출발선에 남은 학생은 그리지 않는다.
- 속도 점수, 순위, 탈락 없음.

### 3.6 보상

| 보상 | 규칙 |
|---|---|
| 오늘의 보상 | 선생님이 이벤트마다 아이템 1개를 골라 대기실에 공개. 둘 중 하나만 달성하면 지급 |
| ㄴ 도전 | 원정 첫 답 정답률 70% 이상 |
| ㄴ 성장 | 원정 첫 답 정답률이 내 평균보다 +10%p (첫 이벤트는 해당 없음) |
| ㄴ 판정 조건 | 원정 문항의 절반 이상에 접속해 있었을 것 |
| 출석 발자국 | 아레나에 들어오면 하루 1개, 누적. 10개마다 발자국 색 1개 |

- 다시 도전, 다시 풀기 결과는 보상에 넣지 않는다.
- v1 이펙트: 착지 먼지, 발자국, 망토 휘날림, 정답 칸 금빛, 3·2·1 출발.

### 3.7 오답 노트 (학생 폰)

- 마무리 때 틀린 단어마다: 단어, 정답 뜻, 내가 고른 답, 헷갈린 이유, 예문, 🔊 발음 (브라우저 내장 읽기).
- [틀린 단어 다시 풀기]: 폰에서 혼자, 한 번 맞히면 통과.
- 내 기록에 남아 다음 주에도 볼 수 있다.

### 3.8 통계 (선생님)

- 학생별: 출석, 이벤트별 정답률, 자주 틀리는 단어, 이제 맞히는 단어, 받은 보상.
- 단어별: 반 정답률 낮은 순, 가장 많이 고른 오답.
- 엑셀로 내보내기.

### `단어장` 시트 (기본)

| 열 | 필수 | 내용 |
|---|---|---|
| 단어 | ✓ | 영어 단어나 구. 다른 철자는 `color\|colour` |
| 뜻 | ✓ | 한국어. 여러 뜻은 쉼표 (과목, 주제) |
| 품사 | | 명·동·형·부·대·전·접·감·구 (목록에서 고름) |
| 헷갈리는 단어 | | 오답 1순위. 여러 개는 `;`. 단어장에 없는 단어는 `quite(꽤)` |
| 예문 | | 빈칸 자리를 `[ ]`로. `Can I [borrow] your pen?` |
| 예문 뜻 | | 정답 공개와 오답 노트에만 |
| 시간(초) | | 비우면 15초 |
| 세트 | | 비우면 `MM-DD 퀴즈` |
| 단원 | | 통계용 |
| 상태 | | 사용(기본) / 검토 / 보관 |
| 단어ID | | 거의 안 씀. 철자가 같고 뜻이 다른 단어만 |

### 앱이 만드는 문제

| 문제 | 예시 |
|---|---|
| 뜻 고르기 | borrow → ① 빌려주다 ② 빌리다 ③ 갚다 ④ 고르다 |
| 단어 고르기 | 빌리다 → ① lend ② bring ③ borrow ④ build |
| 예문 빈칸 | Can I ____ your pen? → ① carry ② borrow ③ lend ④ draw (예문이 있을 때) |

- 원정에서 처음 나온 단어는 뜻 고르기 60%, 단어 고르기 40%. 나온 적 있는 단어는 단어 고르기와 예문 빈칸을 번갈아.
- 오답 보기: 헷갈리는 단어 → 같은 품사 → 철자가 비슷한 단어 순으로 고른다. 뜻이 겹치는 단어(big/large, 아침/아침 식사처럼 한쪽이 다른 쪽을 포함해도)는 같은 문제에 넣지 않는다. 모자라면 지난 이벤트 단어에서 가져온다.
- 예문 빈칸: 괄호 안 글자가 단어와 정확히 같을 때만 만든다(cooks처럼 바뀐 형태면 만들지 않음). 문장에 들어가도 말이 되는 헷갈리는 짝(early/late)은 빈칸 오답으로 쓰지 않는다.
- 정답 위치는 섞되 모두 같은 순서(운동장 칸이 하나니까), 같은 칸 3번 연속 금지.
- 같은 단어는 5문항 이상, 헷갈리는 짝은 3문항 이상 떨어뜨린다.
- 오답 피드백은 자동: 고른 보기의 원래 단어와 뜻을 보여 준다.

### 기록이 이어지는 방식

- 단어 자체(소문자)가 키다. 다음 주에 같은 단어를 올리면 같은 단어로 이어진다.
- 문제 ID는 `단어:모드` (예: `borrow:MEAN`). 뜻이 바뀌면 ID는 두고 버전만 올린다.
- 1~2글자 다른 새 단어가 뜻이 겹치면 "같은 단어인가요?"라고 묻는다 (오타 수정).

### `문항` 시트 (선택)

반의어, 문법처럼 자동으로 만들 수 없는 문제만. 유형 객관식 / OX / 단답형, 정답·해설·피드백1~4·시간(초)을 직접 쓴다. 객관식·OX는 원정 끝 보너스로, 단답형은 폰 입력으로 낸다. 보너스 문제는 정답률·보상·다시 도전에서 뺀다.

### 명단

학생 명단은 단어 파일에 넣지 않는다 (예시 이름이 섞이거나 동료와 파일을 나눌 때 이름이 퍼지지 않게). 선생님 화면 [학생·기기]에서 반을 만든다. 명단은 학생이 처음 접속해 직접 등록하면서 채워지고, 원하면 반마다 '번호 이름'을 미리 붙여 넣어 등록 요청과 맞춰 볼 수 있다. 다른 반 명단은 건드리지 않는다. 학기 말이나 폰 교체 때는 [이 반 기기 모두 해제]로 반 전체를 다시 등록하게 할 수 있다 (기록·캐릭터는 유지). (엑셀에 '명단' 시트(반·번호·이름)가 있으면 그것도 반별로 넣어 준다.)

### 검증

- 필수 칸 누락, 머리글 오타(비슷한 이름 제안), 같은 단어 중복, 오답 후보 부족, 시간 5~60 밖은 행 번호와 함께 알려 준다.
- 정답 칸은 텍스트로 읽는다. ①·1)·(1) 같은 기호와 o·○도 받아 준다.
- `검토` 상태는 저장만 하고 출제하지 않는다.

- **반**: 이름, 명단
- **학생**: 반, 번호(반 안에서), 이름, 캐릭터(머리 모양·색·착용 아이템), 보유 아이템, 출석 발자국
- **기기 연결**: 학생, 기기 토큰(해시), 상태(대기·승인·해지), 확인 기호

- **세션**: 이벤트, 반, 단계(원정·관문·다시 도전·마무리), 현재 문항, 마감 시각, 멈춤 상태

- **보상 기록**: 학생, 아이템, 이유, 날짜

## 6. 기술 구성

- **프로토타입 (지금)**: Next.js 웹앱을 노트북에서 `npm run class`(next build + next start)로 실행한다. 같은 와이파이의 폰이 노트북 주소로 접속한다. 계정 필요 없음.
  - 실시간: 서버→화면은 SSE, 폰→서버는 fetch POST. 로컬 실측(next start, 화면 41개, 초당 이동 320건)에서 유실 0건, 지연 중앙값 약 15ms, p95 약 30ms. 지연은 와이파이가 좌우한다.
  - 진행 엔진(시계, 마감 판정, 보상)은 지금 노트북 서버(`src/server/hub.ts`)가 돌린다.
  - 수업에서는 `next dev` 대신 `next start`를 쓴다 (dev는 p95 70~120ms).
- **교실 운영 (다음)**: Vercel Hobby(페이지, 업로드) + Supabase 서울 리전 Pro(월 $25, DB와 Realtime Broadcast).
  - Vercel 함수는 계속 떠 있지 않으므로 **진행 엔진을 프로젝터 탭(/display)으로 옮긴다.** 서버는 게임 로직 없는 중계만 한다.
  - 구조: 폰 ↔ 프로젝터 탭 1:1 채널 + 프로젝터 탭 → 전원 방송 채널. 폰끼리는 통신하지 않는다.
  - 예상 메시지: 평소 초당 약 70건, 최악 약 340건(Pro 한도 500의 67%), 월 약 30만 건. 폰 쪽에서 초당 4건으로 묶는다.
  - 학생 인증은 지금처럼 서버가 발급한 기기 쿠키 + 세션마다 새 방 코드. 익명 로그인은 학교 NAT 뒤 IP당 시간당 30회 한도 때문에 v1에서는 쓰지 않는다.
  - 대안: Cloudflare Workers + Durable Objects(무료 범위)로 같은 중계를 둔다. Supabase가 자주 끊기거나 한국 지연 p95가 300ms를 넘을 때.
- **이식 순서**: (1) 지금 엔진 동작을 시뮬레이터와 가짜 시계로 테스트에 고정 → (2) 엔진을 순수 TS로 떼어 프로젝터 탭에서 돌리고, 연결은 `HostLink`/`PlayerLink` 인터페이스 뒤에 둠 → (3) 로컬 SSE 어댑터와 Supabase 어댑터를 같은 인터페이스로 → (4) 저장소를 Supabase로. 엔진이 작을 때 옮기는 게 가장 싸다.
- **조심할 점**: 학교 와이파이의 단말 간 격리(첫 주에 실측), 프로젝터 탭이 가려지거나 절전되면 타이머가 늦어짐(창을 항상 보이게, 절전 끄기, 마감 시각 비교로 판정), 이전 주에는 학생 전원이 다시 등록.
- **https가 필요한 것**: 홈 화면 설치, 화면 꺼짐 방지(Wake Lock). 프로토타입에서는 학생에게 화면 꺼짐 시간을 늘리도록 안내한다.
